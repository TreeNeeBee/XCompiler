## 执行合同

- 显式重试仅作用于当前 Phase 中这张 CR 的最新 `deliver` 交付。必须匹配保留输入、原 reporter、原候选和最后一次物理调用，并验证 provider 链和外层请求均已失败。仅有已准备请求、已有未采用的回复候选或审计证据冲突时，继续停止并报告相应错误。
- 每个已证实失败的逻辑请求可登记一个新逻辑请求。不可变凭据记录原交付请求 ID、前次请求 ID、模型调用 ID 及摘要和新请求 ID。重复传入旧 ID 不会再启动一次已发送的请求。如果已登记重试且在捕获新请求前中断，重新执行同一显式命令可以继续。若新请求也已证实失败，进一步重试使用新失败请求的 ID。普通恢复可按关联链读取已经采用的回复。
- 新请求沿用同一 reporter 的模型池绑定。显式覆盖池仍独立，角色默认池可以使用配置中的全局备用。验收结果记在原交付下，由正常流程决定是否关闭 CR 或向下游发出 CR。业务状态和原始记录在本轮只读核验中保持原状。

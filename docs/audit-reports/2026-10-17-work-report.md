## 5. 过程中出现的问题

- **单轮提示的初次对比有误。** 我一开始只比对了系统提示，漏了生产的用户消息提示和 Rule 链，误报了两项缺口。用户追问用途后，我重新核对并更正了文档。最终迁入的是确实缺失的 3 项。
- **证伪发现一个测试没有区分度。** 产出缺失的一项证伪第一次仍然通过；修正测试后才按断言失败。
- 这些都已在审计日志和审计报告中记录。

## 6. 发现的问题（未处理，需要决定）

1. **入口审计与库项目不一致。** 交付审计对所有项目都执行入口 `--help` 探测。
   - Python 库项目没有 `src/main.py` 等入口时会直接判失败。
   - 规划文本（沿用原单轮提示）只要求库提供公共 API。
   - 需要决定：改规划文本还是改审计。
2. **升级时正在进行的项目。** 升级前记录的"缺失产出停滞"失败里没有新字段，这类旧 Bug 的 Debug 重试不再被识别为产出缺失。新记录不受影响。
3. 其余遗留：
   - Debug 判断中还有少量匹配运行时工具错误文本的条款；
   - 一个没有调用方的函数；
   - 交付场景列表在规划阶段不检查。

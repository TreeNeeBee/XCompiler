## 2. 结论摘要

1. **P2 功能主体正确**：19 列表头（前 16 列与 P1 一致）、J1939 PGN/SPN/源地址、扩展多路复用的链路与区间展开、「警告」表、退出码，都与需求一致（见 3.3）。
2. **P2 未能交付**：阶段交付门禁 39 例失败。其中 30 例是 P2 有意的契约演进（19 列、`process_files` 返回三元组）没有同步到 P1 的基线与补充测试，9 例是一个真实的产品缺陷（失败文件的警告泄漏）。
3. **产品缺陷被改写契约掩盖**：S002 曾正确诊断这个缺陷，并试图提交给 CODE，但被 D-67 修复前的校验器误报阻断；后续尝试改为在高层设计中加入一个互相矛盾的"附录 A"，并放宽了模块测试。缺陷留在交付代码中。
4. **用户文档没有更新**：README 与 quickstart 仍是 P1 内容，明确写着"不包含扩展多路复用、J1939 语义"，以及"固定 16 列"。
5. **D-66、D-67 在真实 run 中按设计生效**，消除了此前反复导致尝试失败的三类模式（见第 4 节）。
6. **run B 的停止是 XCompiler 的结构缺陷**：前序阶段的回归测试资产在当前阶段没有可写的所有者，而门禁失败输出只保留末尾几行，路由只看到 39 例中的 1 例（见第 5 节，需要决定）。

## 3. 业务交付质量

### 3.1 需求（`docs/02-requirement-analysis-p2.md`）— 良好

- P2-R1～R6 与 NR-1～NR-9 可测，退出码、工作表顺序、"警告不改变退出码"写得明确。
- 4.2 节对复用链路的构建、展开和列取值格式（含 `m<N>M` 与多层链路）给出了精确表格，是实现与测试的可靠依据。

### 3.2 设计（`docs/03-high-level-design-p2.md`、`docs/04-detailed-design-p2.md`）— 有缺陷

- 正面：`process_files` 改为返回 `(rows, errors, warnings)` 三元组，§113、§248 写明；§256 写明"读取/解析异常 → `ErrorRecord`，不产生该文件的信号行与警告行"。
- **缺陷 D1：两个同名、互相矛盾的"附录 A"**（commit `6c718c3`）。第一个要求逐文件独立的警告缓冲、失败即丢弃，由 CODE 实现；第二个裁定保留失败文件的警告"属于实现自由度"。第二个与 §256 以及第一个附录直接冲突。
- 缺陷 D2：P2 改变了 P1 的公开契约（16 → 19 列、二元组 → 三元组），但设计没有列出受影响的 P1 基线与补充测试，也没有安排更新它们。

### 3.3 代码（`src/`）— 功能正确，有 1 个缺陷

实测（`samples/ext_mux.dbc`、`samples/j1939.dbc`、`samples/broken_p2.dbc`）：

| 检查 | 结果 |
| --- | --- |
| 表头 | 19 列，前 16 列与 P1 一致，追加 `J1939 PGN` / `J1939 SPN` / `J1939 源地址` |
| J1939 | `EEC1.EngineSpeed`：PGN 61444（0xF004）、SPN 190、源地址 0，与 J1939 定义一致；无属性时留空 |
| 扩展复用 | `MuxSwitch` 是/空；`SubSwitch`（`m1M`）是/`MuxSwitch=1`；`RangeSignal`（`1-3`）展开 3 行 `1`/`2`/`3`；`SubValueX` `MuxSwitch=1;SubSwitch=3`；`AlwaysOn` 否/空。与需求 4.2.4 逐项一致 |
| 警告表 | 未知段与未声明属性各记一行；无警告时不建表 |
| 退出码 | 全部成功为 0（有警告仍为 0）；含坏文件为 1 |

- **缺陷 C1：失败文件的警告泄漏**。`src/main.py:76` 把全局 `warnings` 传给 `parse_dbc`，坏文件抛出 `DbcParseError` 前追加的警告留在结果中。`broken_p2.dbc` 的每行说明文字都成了一条警告，"段/属性类型"列是该行的第一个词（如"这不是一个有效的"）。这违反高层设计 §256 与需求的警告语义，用户会在「警告」表看到无意义的记录。

### 3.4 测试 — P2 新测试通过，回归资产未更新，一处被放宽

完整运行 `pytest tests`：396 通过，39 失败。

| 类别 | 例数 | 原因 | 正确处理 |
| --- | --- | --- | --- |
| 表头 16 → 19 | 19 | P1 单元、模块、功能测试和 P1 补充测试断言 `len(header) == 16` 或完整 16 列 | 按 P2 契约改为前 16 列一致 + 3 列追加 |
| `process_files` 返回值 | 11 | P1 测试按二元组解包 | 按三元组更新 |
| 工作表列表多出「警告」 | 9 | 全部是坏文件或全部失败的场景，由缺陷 C1 引起 | 修复产品代码，不改测试 |

- 缺陷 T1：模块测试 `test_process_files_broken_file_yields_error_and_no_rows` 被改为只断言"警告归属该失败文件"，接受了缺陷 C1。

| 打包产物 | `dist/pkg` 仍是 `62e10a7` 的构建，不含 D-68～D-70 |

本阶段确立的硬规则：**每个完成的阶段都是里程碑，后续阶段严禁造成功能回退。** 没改动的前序测试必须继续通过；要改动，必须登记本阶段已接受的契约依据。

这条规则目前的强度有明确边界：功能层级（用户可见行为）除引用校验外还要经过语义判定；模块、集成、单元层级只校验引用真实、层级合规，**挡不住引用真实存在但实际无关或有误的条款**。dbc2excel-5 里已有一个这样的实例，重跑前需要处理（第 4、7 节）。

## 3. 里程碑不回退规则（D-68、D-69）

**P2 能改 P1 的哪些产物：**

| P1 产物 | 能否修改 |
| --- | --- |
| 产品代码 `src/*.py` | 能。CODE 直接声明这些文件，产品在原文件上演进 |
| 同层级的可执行测试 | 能，但必须登记契约依据 |
| 需求、设计文档、测试报告、P1 交付门禁报告 | 不能 |
| 根目录 `README.md`、`docs/quickstart.md` | 不能。P2 没有 Step 负责它们（缺陷 U1 的根因） |

**逐层检查：**

1. **写入时**：执行器在工具派发点、权限询问之前检查。缺依据或依据无效时返回 `contract_basis_refused`，不询问用户、不执行工具。
2. **依据校验**（`resolveContractBasis`，确定性）：
   - 形式为当前阶段文档路径加逐字引用，或已接受 CR 的 `ticketId`；
   - 层级：功能测试只能引用需求或 CR；模块测试可引用需求、概要设计；集成、单元测试可引用需求、概要设计、详细设计；
   - 引用按 **本 Ticket 基线版本** 校验，用 `git show` 读取。本 Ticket 自己写入的文字不算已接受的契约，防止先写条款再引用；
   - 引用不少于 8 个非空白字符；
   - CR 必须在受影响文件中列出该测试。
3. **语义判定（仅功能层级）**：`REQUIREMENT_ANALYSIS`、`FUNCTIONAL_TEST` 的写入，由 PM 经 Rule 绑定的请求判断引用是否真的取代原断言。判否、未配置判定、判定内容无效都拒绝写入；模型服务故障按基础设施失败抛出。
4. **登记**：写入成功后才写入 `Ticket.contractBases`（只追加），并带文件内容哈希。被拒、失败的写入不留登记。
5. **交付前复核**：`git diff` 加工作区，取本 Ticket 改过的继承资产，比对路径和当前内容；没有对应登记时以 `inherited_test_change_unregistered` 判尝试失败。用来拦住 `run_program` 副作用、路径绕过等不经过写入检查的改动，旧登记也覆盖不了后来变了内容的文件。
6. **门禁运行范围**：开发 Step 跑本阶段基线和本 Ticket 改过的继承测试；验证 Step 跑本层级完整测试；阶段门禁全量运行，没改动的 P1 测试必须通过。测试运行失败时门禁始终保留失败检查。
7. **留痕**：发出 `domain.contract_basis_registered`，并在阶段交付门禁报告中列出全部登记。

## 8. 剩余风险与待决事项

| 事项 | 影响 | 状态 |
| --- | --- | --- |
| 模块、集成、单元层级没有语义判定 | 引用真实但无关的条款可以通过 | 用户选择只在功能层级加 |
| 语义判定的质量 | 尚无真实模型证据；判定规则未经实际案例校准 | 待重跑验证 |
| 没有用户入口提交 CR | `external-usage` 入口是预留的，调用即报错；`evolve`、`append` 要求项目已关闭。D1、T1 目前无法以 CR 形式进入 P2 | **待决定，阻塞重跑** |
| P2 自有测试不受保护 | 继承规则只覆盖前序阶段资产，T1 这类放宽拦不住 | 待决定 |
| G3：门禁 Bug 不带失败用例 | 修复 Step 的门禁不跑未改动的失败用例，要等下一次阶段门禁才知道修得对不对；多绕轮次，不会死锁 | 用户本轮未选 |
| 无阶段级对账 | 门禁不把"自里程碑以来改过的继承测试"与账本逐一核对，依赖每次交付的复核。Ticket 被放弃时，保留候选里未登记的改动可能漏检 | 未做 |
| 前一张 Ticket 写入的文字可被后一张引用 | 基线校验只阻止同一 Ticket 自我论证 | 已知，D1 属于此类 |
| 一个根因报给 CODE 多次 | 多个负责方可能分别报告同一缺陷，目前靠证据中的完整用例列表关联 | 已知 |
| 结构化失败列表只支持 pytest | TypeScript 项目仍整体路由到 CODE | 已知 |
| G5、X-4～X-7 | 交接文字不含继承测试；文档内容无门禁；只读指纹不含修改代次；推理无预算预留；其他协议缺截断提示 | 待决定 |
